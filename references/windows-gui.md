# Windows原生操作的实践经验

这份参考针对CE2.0.9.7b_beta的一次系列操作，不固定exe路径、窗口ID、元素索引或点击坐标。自动化使用当前环境明确支持的电脑控制API；若提供Computer Use skill，先按其文档初始化。不要混用shell/UIA和受控桌面输入来绕过当前工具要求。

## 观察、操作、确认

- 枚举当前应用/窗口，按真实返回的版本标题与进程筛选唯一对象。前次句柄不能当新会话证据。
- 先观察当前状态，再操作控件并复查。界面或焦点变化后，不沿用旧索引。数值输入后检查目标字段和实际保存值。
- QBlade主窗口状态可能拼接模态框的树，但动作不一定能经主窗口命中子窗。发现元素不可用时重新枚举窗口及应用、绑定实际模态框；不要盲目重复Save/Start。
- 主窗截图有时因标题栏位置造成坐标偏移；菜单、对话框还可能是独立截图区域。依据当前API坐标规则选择区域。可用已观察的菜单键盘导航，不能凭记忆反复点击。
- 电脑锁屏、身份验证或不可控制的安全界面交给用户；未观察到结果时报告状态未知，而不是声称完成。

## 原生项目和对象

先Save As建立工作项目，确认磁盘文件。修改几何或流体设置前建立独立对象/备份。编辑后换新名保存，在一次版本中确实保留基准，但需用实际对象列表确认复制行为，不能把重命名误当复制。

Optimize的Done可能恢复源对象名称；保存前重新检查名字。项目栏星号、状态提示和磁盘文件的时间/大小/哈希可以配合核对，但任何单一提示均不证明全部模型内容正确。

进入HAWT/VAWT后重新核对模块与参数语义。Root Coordinates开关会改变位置显示；四舍五入后的0.02 m不应覆盖已有精确0.018 m输入。

## 原生批次与导出

先核对选中的foil、Re/α范围、Ncrit和XFOIL参数，然后真实Start。观察完成后的对象数和保存点，导出XFOIL有限角度表，保留设置。GUI批次完成不是所有请求角度都成功。

导出采用界面当前支持的入口，并检查实际路径、扩展名和依赖。目录选择器与文件名框不同，按当前状态操作；遇到未知结果先看文件是否已产生，避免重复导出或覆盖。

官方[CLI文档](https://docs.qblade.org/src/user/interfaces/commandline.html)标为EE功能。不要编造CE批处理参数，也不要把打开qpr、等待固定时长、超时杀进程当成仿真完成。
